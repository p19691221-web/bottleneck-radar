    上架代表什麼

    上架只代表整理者確認來源存在，並補上了瓶頸分類與證據強度。它不是對事件的判定，也不代表事件描述一定正確。

    證據強度

    • 原始紀錄：日誌、判決、監管文件等可核對的一手資料
    • 當事方聲明：涉事公司或機構自己的說法
    • 媒體轉述：媒體或第三方的整理與引述

    訊號類型

    • 已有人付出成本：已出現損失、重建或事故處理
    • 塞車跡象：量或速度超過既有配套，尚未見損失
    • 平台吸收：控制被平台或必經關口內建
    • 治理先行：規範或委員會先於問題出現
    • 歷史先例：AI 之前的同類事件，只作對照

    參與方式 · How to take part

    回報與討論都在 GitHub 上進行，需要一個免費帳號。請用自己的話描述事件，附上來源連結，不要貼文章原文。卡片上的 👍 代表「我也看到類似情況」。

    Reports and discussion run on GitHub (free account). Use your own words and link the source. 👍 means "I've seen this too."

    我能解這個 · I can solve this

    能處理某個瓶頸的人或團隊，可以在那則訊號下留一份回應：能解哪一段、能力證據、公開聯絡方式。整理者確認證據連結存在後才會顯示。顯示只代表連結存在，不代表能力已被驗證，也不是推薦。

    If you can address a bottleneck, leave an offer on that signal: what you solve, an evidence link, a public contact. It appears once the link is checked. Listing is not verification or endorsement.
